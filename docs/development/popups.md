# Widget and menu interaction standard

## Current Quickshell runtime

The current component and layout contract is documented in [controls.md](controls.md). `quickshell/shell/PopupManager.qml` tracks independent main surfaces by output and menu name, plus registered child menus and popovers. Left, right and activity menus have separate `SurfaceHost` windows and can remain open together, including across outputs. Each trigger toggles only its own surface. Opening another main surface or child does not close its siblings. Closing a main surface closes only children anchored to it; output disposal closes only that output’s surfaces. A single shared focus grab includes all bars, visible hosts and every registered child branch window, so clicking within another menu keeps siblings open. Outside dismissal and screenshot preparation close the entire session. Escape closes the latest child before the latest main surface. A tray branch may contain several native popup windows; its owner exposes all branch windows to the shared focus group. Escape closes the deepest focused submenu first, while Escape handled by `PopupManager` dismisses the registered child before its parent. Tooltips and passive hover detail popovers keep their separate behavior.

`MenuPointerIntent` uses one geometry and timing policy for dropdowns and cascading menus. Its safe region is the buffered convex hull of every corner of the actual source and target rectangles. This follows the real left/right/up/down placement, including flipped, touching and negative-coordinate rectangles. While a pointer-dismiss branch is open, the root controller polls Hyprland's read-only `j/cursorpos` request every 40 ms, with one request in flight and a 150 ms timeout, then shares the normalized point with descendants. Cursor entry into the hull cancels outside timing; only an observed point outside starts the 350 ms grace. A fresh point more than 80 logical pixels from every rectangle in the connected branch may close early. An unobserved native-window gap cannot start dismissal. Outside clicks and Escape remain immediate. Holding a pointer button suspends dismissal.

Hovering an enabled submenu row for 180 ms opens it; leaving that row, changing the model, using the keyboard or clicking cancels the pending open. Click and keyboard navigation open immediately. While the pointer remains inside the hull, menus stay open without a deadline. Pointer dismissal remains disabled for main drawers, editable controls, slider popovers, the audio mixer, and telemetry detail popovers. Telemetry details open and close on a left click of the capsule; hover does not open them, and click-away or Escape dismisses them.

Tray context menus can show a translucent green pointer-intent debug overlay. It marks the actual anchor and menu rectangles, the same active buffered hull used for dismissal, and the last observed pointer. The overlay passes pointer and keyboard input through and disappears with the menu. It is hidden by default; set `PENTAD_MENU_POINTER_DEBUG=1` to show it.

Tray content height is derived directly from the model (30 px per row, 9 px per separator), so an asynchronously populated menu does not wait on an initial Column implicit-height polish. AttachedPopover requests a frame after requested size changes and retries at most eight times, 32 ms apart, stopping once native and requested heights match or the window closes. This addresses the observed native/requested size mismatch, though the exact compositor cause is not established.

Tray context menus read their DBusMenu tree with Quickshell's `QsMenuOpener`. Nested entries open in cascading `AttachedPopover` side panels. A single registered tray-menu owner exposes the complete branch to the focus group and closes every level when a leaf action runs or the owner closes. This keeps menu rendering inside Pentad's theme and does not call the platform menu API, which requires starting Quickshell in QApplication mode.
